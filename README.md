# DBF → PostgreSQL

Консольное приложение на C# / .NET 8. Читает все `.dbf` / `.DBF` в указанной папке и добавляет записи в одну таблицу PostgreSQL. Кодировка по умолчанию — **русская DOS CP866**.

## Настройка и запуск

Нужны .NET SDK 8 и доступная база PostgreSQL. База и схема должны существовать; пользователь PostgreSQL должен иметь права на создание таблиц в схеме, изменение целевой таблицы и запись в неё.

Отредактируйте `src/DbfToPostgre.Console/appsettings.json`:

```json
{
  "Import": {
    "FolderPath": "C:\\Data\\Dbf",
    "ConnectionString": "Host=localhost;Port=5432;Database=dbf_import;Username=postgres;Password=YOUR_PASSWORD",
    "SchemaName": "public",
    "TableName": "dbf_data",
    "EncodingCodePage": 866
  }
}
```

Из каталога решения:

```powershell
dotnet run --project src/DbfToPostgre.Console
```

Для запуска без SDK:

```powershell
dotnet publish src/DbfToPostgre.Console -c Release -o publish
dotnet ./publish/DbfToPostgre.Console.dll
```

Для второго варианта нужна среда выполнения .NET 8. Настройки читаются из каталога приложения. Относительный `FolderPath` отсчитывается от рабочего каталога запуска; для однозначности используйте абсолютный путь.

Пароль можно задать переменной окружения `Import__ConnectionString`. Настройки также можно переопределить через `appsettings.Local.json` рядом с собранным приложением; этот файл исключён из Git. Не коммитьте реальные пароли в `appsettings.json`.

## Поведение импорта

- Поиск выполняется в самой папке, без подпапок. Приложение заканчивает работу после обработки файлов.
- DBF могут иметь разный набор и порядок полей. Поля сопоставляются по имени, имена приводятся к нижнему регистру через `ToLowerInvariant()`.
- Если таблицы нет, создаётся таблица с полями DBF и `id bigserial PRIMARY KEY`. Значения `id` генерирует PostgreSQL.
- Перед загрузкой каждого файла недостающие столбцы добавляются в таблицу с типами из DBF. В ранее записанных строках новые столбцы получают `NULL`. PostgreSQL добавляет столбцы в конец таблицы; на сопоставление по имени их позиция не влияет.
- Для столбцов таблицы, отсутствующих в текущем DBF, явно записывается `NULL`, даже если у них задан `DEFAULT`. Поле `id` по-прежнему заполняется PostgreSQL. Существующие строки не изменяются.
- Типы, длина и точность уже существующих полей должны совпадать с DBF. Несовместимые типы, отсутствие автоматически генерируемого `id`, вычисляемые столбцы помимо `id` или запрет `NULL` для отсутствующего в DBF поля вызывают ошибку. Ограничения таблицы автоматически не удаляются.
- Записи передаются потоком через бинарный `COPY`, без загрузки всего файла в память. Имена схемы, таблицы и полей экранируются.
- Каждый файл обрабатывается в отдельной транзакции вместе с добавлением столбцов. При ошибке или Ctrl+C данные текущего файла и добавленные для него столбцы откатываются, ранее успешно импортированные файлы остаются в базе. При ошибке дальнейший импорт останавливается, в сообщении указывается файл. На время импорта файла запись в таблицу из других подключений блокируется для согласования структуры.
- Записи с отметкой удаления пропускаются. Пустые строки и строки только из пробельных символов, пустые числа, даты и неизвестные логические значения сохраняются как `NULL`. У непустых строк удаляются завершающие пробелы, начальные сохраняются.
- Обнаруженные неподдерживаемые типы, обрезанные файлы и некорректные значения числовых полей `N` вызывают ошибку. Для memo-полей соответствующий `.dbt` / `.fpt` должен находиться рядом с DBF.
- **Повторный запуск добавляет записи повторно.** Учёта импортированных файлов и удаления дублей нет, поскольку в DBF нет заданного уникального ключа.
- Коды завершения: `0` — успех, включая отсутствие файлов; `1` — ошибка; `2` — отмена.

## Типы полей

| DBF | PostgreSQL |
| --- | --- |
| `C` — строка | `varchar(длина)` |
| `N` — число | `numeric(длина, десятичных_знаков)` |
| `I` — целое | `integer` |
| `F` — число с плавающей точкой | `real` |
| `B` — double | `double precision` |
| `Y` — currency | `numeric(19,4)` |
| `D` — дата | `date` |
| `T` — дата и время | `timestamp without time zone` |
| `L` — логическое | `boolean` |
| `M` — текстовый memo | `text` |

`N` читается как .NET `decimal`, включая целые числа больше `Int64`. Значения, выходящие за диапазон `decimal` (около 28–29 значащих цифр), отклоняются. OLE/General (`G`), бинарные поля и другие отсутствующие в таблице типы отклоняются. Для чтения используется [DbfDataReader](https://github.com/yellowfeather/DbfDataReader); для работы с PostgreSQL — [Npgsql](https://www.npgsql.org/doc/copy.html).

## DI и перенос в веб

`src/DbfToPostgre` — библиотека без зависимости от консольного интерфейса. `src/DbfToPostgre.Console` содержит настройки, построение Generic Host и запуск. Чтение и запись выделены в `IDbfReader` и `IPostgresWriter`; импорт доступен через `IImportService`.

В ASP.NET Core подключите библиотеку и зарегистрируйте те же службы:

```csharp
using DbfToPostgre;

builder.Services.AddDbfImport(builder.Configuration);
```

Внедрите `IImportService` в обработчик или фоновую службу и вызовите:

```csharp
await importService.ImportAsync(cancellationToken);
```

Один вызов обрабатывает всю папку. Одновременные вызовы для одной папки добавят те же записи повторно.

## Проверки

```powershell
dotnet test
```

Автономные тесты создают DBF в CP866 и проверяют кириллицу, большие числа, даты, удалённые записи, повреждённые файлы, импорт файлов с разной структурой, преобразование пустых строк в `NULL`, отмену, DI и SQL-имена.

Для интеграционного теста задайте строку подключения к тестовой базе:

```powershell
$env:DBF_TEST_CONNECTION_STRING = 'Host=localhost;Database=dbf_tests;Username=postgres;Password=YOUR_PASSWORD'
dotnet test
```

Интеграционные тесты создают таблицы со случайными именами `public.dbf_test_*` и проверяют создание и добавление полей, сопоставление по имени, явные `NULL` вместо значений `DEFAULT`, генерацию `id`, откат данных и изменений структуры, отказ от несовместимых типов и ограничения `NOT NULL`. В конце каждый тест удаляет созданную им таблицу. Без переменной окружения эти тесты пропускаются.
